# 无限画布 AI 动漫创作工具 开发报告

## 1. 项目背景与目标
本项目旨在构建一个基于**无限画布**的 AI 动漫创作平台，用户通过拖拽、连接**可视化工作流节点**，自由编排文本、图片、视频、音频等素材，调用多种生成式 AI 模型，实现图像、音频、视频的自动化创作。系统采用 **WeiUI 组件库** 统一视觉与交互规范，支持**多人实时协同**操作，并为未来新增组件预留标准化接口。

核心目标：
- 提供**无边界画布**，支持节点的自由放置、拖拽、缩放与连线。
- 实现 **7 类核心节点**：文本、图片、视频、音频（输入型）及图片生成、视频生成、音频生成（功能型），严格遵循连接规则。
- **多人协同**：实时同步节点位置、连线、参数，用户操作时显示对应身份标识。
- 高度**可扩展**的组件注册机制，便于后期添加新 AI 模型与媒体类型。
- 保证**高性能**，支持上千节点流畅交互。

---

## 2. 系统总体设计
系统采用前后端分离架构，前端负责画布渲染、交互与协作状态管理，后端提供实时同步、AI 任务调度与媒体存储服务。

**架构示意图（文字描述）**：  
`[浏览器端] 画布引擎 + WeiUI 节点组件 → WebSocket 同步 ← [协作服务器] CRDT 合并 ↔ [AI 服务] 模型推理`  
媒体文件通过 CDN 加速分发，AI 任务以异步队列处理。

关键技术点：
- 前端状态管理：本地 Zustand（画布状态）+ Yjs（协作数据）
- 画布渲染：基于 Canvas 或 WebGL 的自定义引擎，或成熟库（如 React Flow / XYFlow）深度定制，实现无限画布特性
- UI 框架：WeiUI（提供按钮、弹窗、输入框等基础元素）
- 协作协议：WebSocket + Yjs CRDT 实现无冲突复制数据类型
- AI 集成：统一的任务调度接口，支持文生图、TTS、视频生成模型

---

## 3. 核心模块设计

### 3.1 无限画布引擎
- **视口管理**：支持鼠标滚轮缩放（0.1x ~ 5x）、空格+拖拽平移、触摸手势（移动端）。
- **坐标系**：使用世界坐标，节点位置为 `(x, y)` 浮点数，不受视口变换影响。
- **性能优化**：
  - 视口裁剪：仅渲染可视区域内的节点与连线，采用四叉树或 R-Tree 空间索引。
  - 节点虚拟化：大量节点时，屏幕外节点使用占位符或简略渲染。
  - 连线批量绘制：单次 Canvas 绘制所有可见贝塞尔曲线。
- **交互**：节点拖拽移动、多选（Shift+点击或框选）、右键菜单、连线拖拽吸附到端点。

### 3.2 节点系统（基于 WeiUI 定制）
所有节点均为**统一格式的 React 组件**，通过注册器动态加载。基础结构：
```typescript
interface BaseNode {
  id: string;
  type: string;           // 组件类型标识
  position: { x: number; y: number };
  data: Record<string, any>; // 组件特有数据
  inputs: Port[];         // 输入端口
  outputs: Port[];        // 输出端口
}
interface Port {
  id: string;
  type: 'text' | 'image' | 'video' | 'audio'; // 数据类型
  label: string;
  connectedTo?: { nodeId: string; portId: string }[];
}
```
- **输入组件（数据源）**：
  - **文本节点**：输出端口类型为 `text`，data 包含 prompt 字段。
  - **图片/视频/音频节点**：输出端口类型对应媒体，data 包含文件引用（URL / base64），支持本地上传或从素材库选择。
- **功能组件（生成器）**：
  - **图片生成**：必须含有一个 `text` 类型输入端口（必需），以及多个 `image` 类型输入端口（可选，用于参考图）。输出端口为 `image`。
  - **音频生成**：必须含有一个 `text` 输入端口，输出 `audio`。
  - **视频生成**：必须含有一个 `text` 输入端口，可选 `image`、`video`、`audio` 输入端口，输出 `video`。

每个节点的 UI 基于 WeiUI 的卡片组件，包含标题、端口圆点、状态指示、用户头像标识等。

### 3.3 连接规则引擎
实现一个 **验证器**，在用户尝试连线时实时检查：
- 端口数据类型必须匹配（如 `text` → `text` 输入）。
- 功能组件的必需端口必须已连接才可执行（“生成”按钮点亮）。
- 图片生成组件：必须至少连接一个 `text`，可选多个 `image`。
- 音频生成组件：必须连接一个 `text`。
- 视频生成组件：必须连接一个 `text`，其余可选。

验证逻辑封装为纯函数，方便扩展新组件规则。

### 3.4 数据模型（画布状态）
```typescript
interface CanvasState {
  nodes: Map<string, BaseNode>;
  edges: Edge[];
  viewport: { x: number; y: number; zoom: number };
}
interface Edge {
  id: string;
  sourceNodeId: string;
  sourcePortId: string;
  targetNodeId: string;
  targetPortId: string;
}
```
协作时，整个状态被 Yjs 的 `Y.Map` 和 `Y.Array` 表示，实现自动同步。

### 3.5 AI 模型集成
提供统一的 **AI Task Manager**：
- 前端通过 WebSocket 或 HTTP 发起任务，携带节点 ID 及其输入数据（从连接的上游节点拉取实际内容）。
- 后端将任务放入队列，按模型类型调度（如 Stable Diffusion、VITS、VideoCrafter 等）。
- 生成过程中，节点显示进度条；完成后，结果回写至节点 data，并推送给所有协作者。
- 支持**中断**与**重试**机制。

## 4. 多人协作方案
- **实时同步**：基于 Yjs + y-websocket 协议，画布状态（节点、连线、视口）作为共享数据类型同步。每个操作（移动节点、添加连线、修改参数）自动生成增量更新，通过 WebSocket 广播。
- **用户标识**：
  - 每个连接有唯一 `userId`、颜色、昵称。
  - 当用户 A 正在编辑某个节点的属性（如输入提示词、调整参数）时，将该节点“锁定”并显示用户 A 的头像浮层，锁定期间其他用户只能查看不可编辑。
  - 拖拽节点时同理，实时广播节点位置，显示 A 的光标/头像指示。
- **冲突处理**：利用 Yjs 的 CRDT 算法自动合并（如最后写入者胜出、无冲突数据类型），避免加锁。对于节点属性编辑，采用细粒度 Y.Text 或 Y.Map，支持并发修改。
- **感知信息**：显示在线用户列表，每个用户头像在画布角落或节点旁浮动。

## 5. UI/UX 设计（融合 WeiUI）
- **画布界面**：最小化工具栏（保存、导出、撤销/重做、协作按钮），底部状态栏显示在线人数。
- **节点样式**：遵循 WeiUI 的扁平化、圆角、柔和阴影，不同类型节点用不同主题色（输入：蓝，生成：紫）。
- **连接线**：贝塞尔曲线，可显示流动动画（数据流向）。断开时可拖拽。
- **右键菜单**：WeiUI Actionsheet 风格，提供删除、复制、锁定、运行等操作。
- **侧边栏**：可拖拽的组件库面板，列出所有可用节点类型，支持搜索，拖入画布创建实例。
- **响应式**：支持触屏设备，节点最小点击区域 44px，端口拖拽易于手指操作。
- **动画**：节点创建/删除淡入淡出，连线流动，生成时进度光效。

## 6. 扩展性设计（组件插件化）
定义统一的 **组件注册接口**，便于后期添加如“风格迁移”、“视频编辑”等新节点。
```typescript
interface ComponentPlugin {
  type: string;                // 唯一标识
  name: string;                // 显示名称
  category: 'input' | 'function' | 'output';
  ports: PortDefinition[];     // 输入输出端口定义
  defaultData: any;
  validator?: (node: BaseNode, edges: Edge[]) => boolean; // 自定义连接规则
  component: React.FC<NodeProps>; // UI 组件
}
```
插件通过 `PluginRegistry.register(plugin)` 动态添加，侧边栏自动更新，无需修改核心代码。

## 7. 技术栈选型
| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | React 18 + TypeScript | 组件化开发 |
| UI 库 | **WeiUI**（假设为内部组件库） | 统一风格 |

| AI 任务调度 | BullMQ + Redis | 异步队列，可扩展 |
| 存储 | AWS S3 / MinIO (媒体) + PostgreSQL (元数据) | 可靠与可扩展 |
| 部署 | Docker + Kubernetes | 微服务化 |

## 8. 性能优化细节
- **画布渲染**：只绘制视口内节点，连线使用离屏 Canvas 缓存静态部分，拖拽时实时重绘动态连线。
- **节点池**：删除节点不立即销毁 DOM，而是回收复用，减少 GC。
- **懒加载**：媒体内容仅在节点进入视口或点击预览时加载缩略图/低分辨率版本。
- **协作更新节流**：节点拖拽期间，位置同步控制在每秒 30 次广播，避免网络洪流。
- **Web Worker**：将复杂校验、AI 任务状态轮询等移至 Worker，避免主线程卡顿。
- **增量保存**：用户每次操作后自动保存至本地草稿，协作版则依赖服务端持久化。

## 10. 风险与应对
- **AI 模型耗时过长**：采用任务队列，前端轮询或 WebSocket 推送进度，避免超时假死；提供生成历史缓存，相同输入可复用结果。
- **协作冲突导致数据不一致**：充分测试 Yjs CRDT 边界情况，复杂属性（如媒体文件）操作实现原子化。
- **无限画布内存泄漏**：严格执行节点生命周期管理，使用 `WeakMap` 关联事件监听，销毁时解绑。
- **WeiUI 版本不兼容**：前期锁定版本，并封装一层适配器，方便未来切换 UI 库。
